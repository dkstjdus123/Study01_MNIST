# CLAUDE.md (web_version)

브라우저에서 손글씨 숫자를 인식하는 웹 버전입니다. **외부 라이브러리 없이 순수 자바스크립트로 추론**하며, 빌드 과정 없이 GitHub Pages에 정적 파일로 올립니다. 루트 `CLAUDE.md`의 공통 규칙을 따릅니다.

## 파일

- `index.html`, `스타일.css`: 화면 (맨 위 학번·이름 표시줄, 그림판, 결과 영역). 스크립트는 그림판 → 전처리 → 모델 → 앱 순서로 불러옵니다.
- `그림판.js`: 캔버스 그리기 (포인터 이벤트로 마우스 + 터치). 검은 배경에 흰 글씨. 한 번에 한 포인터만 그리고(두 번째 손가락 무시), 마우스는 왼쪽 버튼만 씁니다. 스타일의 `touch-action: none`을 지우면 휴대폰에서 그릴 때 화면이 스크롤됩니다.
- `전처리.js`: `desktop_version/app.py`의 `전처리()` 이식.
- `모델.js`: 가중치 적재 + 순전파 (합성곱 3x3·패딩 1, ReLU, 2x2 최대풀링, 전결합).
- `앱.js`: 위 셋을 엮어 붓을 뗄 때마다 인식하고 예측·신뢰도·확률 막대를 표시.
- `가중치.bin`, `가중치정보.json`: `desktop_version/가중치내보내기.py`의 산출물. 직접 고치지 않습니다.
- `검증.html`: 파이썬 결과와 대조하는 검증 페이지.

## 로컬 실행법

```bash
python -m http.server 8000     # 저장소 루트에서 실행 (맥·리눅스는 python3 -m http.server 8000)
```

- 웹 앱: http://localhost:8000/ (루트 `index.html`이 `web_version/`으로 이동) 또는 http://localhost:8000/web_version/
- **`file://`로 index.html을 직접 열면 안 됩니다.** 브라우저가 `fetch`로 가중치 파일을 읽는 것을 막습니다. 이때 화면에 로컬 서버로 여는 방법이 안내됩니다. 반드시 로컬 서버로 엽니다.

## 가중치.bin 형식

- 헤더 없는 순수 데이터입니다. float32 **리틀 엔디언** 값을 텐서 12개(합성곱 4개 + 전결합 2개의 weight/bias)만큼 순서대로 이어 붙였습니다 (약 3.5MB).
- 배치정규화는 합성곱에 미리 합쳐져 있으므로 따로 없습니다.
- 각 텐서의 위치는 `가중치정보.json`의 `층[].가중치/편향`에 `형상`, `오프셋`(float 개수 단위, 바이트는 ×4), `개수`로 적혀 있습니다. `모델.js`는 `new Float32Array(바이너리, 오프셋 * 4, 개수)`로 복사 없이 읽습니다.
- 메모리 순서는 PyTorch와 같습니다: 합성곱 가중치 `[출력채널][입력채널][3][3]`, 전결합 가중치 `[출력][입력]`, 전결합 입력은 Flatten 순서 `[채널][높이][너비]`.
- `가중치정보.json`에는 정규화 상수 `평균`, `표준편차`도 들어 있습니다. 자바스크립트에 상수를 따로 적지 않습니다.

## 파이썬과 맞춰야 할 지점

- **전처리** (`전처리.js` ↔ `app.py`의 `전처리()`): 같은 순서와 같은 계산이어야 합니다.
  - 축소는 PIL `Image.LANCZOS`를 그대로 구현했습니다 (가로 먼저 → 세로, 22비트 고정소수점 계수, 8비트 반올림). 브라우저 `drawImage` 축소로 바꾸면 결과가 달라집니다.
  - 크기와 이동량 반올림은 파이썬 `round()`처럼 정확히 .5일 때 짝수 쪽으로 합니다 (`파이썬반올림`).
  - 28x28 배치 위치는 `(28 - 크기) // 2`, 무게중심 이동 후 빈 곳은 0(검은색).
- **모델 구조** (`모델.js` ↔ `desktop_version/model.py`): 층 종류가 늘거나 합성곱 크기·패딩이 바뀌면 `가중치내보내기.py`와 `모델.js`를 함께 고칩니다.
- **정규화 상수**: `가중치정보.json`에서 읽으므로 `가중치내보내기.py`를 다시 실행하면 자동으로 맞춰집니다.
- **그림판**: 펜 두께 18px, 캔버스 280x280, 검은 배경에 흰 글씨 (`app.py`와 같음).
- 재학습하면 반드시 `python desktop_version/가중치내보내기.py`를 다시 실행하고 커밋해야 페이지에 반영됩니다.

## 검증 절차

1. `python desktop_version/검증데이터만들기.py` → `검증데이터.json/.bin` 생성 (`.gitignore`로 제외, 약 18MB). 표본은 MNIST 10배 확대 50장, 크기·위치를 바꾼 MNIST 150장(일부 가장자리 접촉), `app.py` 방식으로 그린 획 30장입니다.
2. 저장소 루트에서 `python -m http.server 8000` → http://localhost:8000/web_version/검증.html
3. 요약이 **통과**이고 성공 기준 표의 네 항목(순전파 일치: 같은 28x28 입력의 확률 최대 절대차 ≤ 1e-4, 전처리 일치 100%, 예측 일치 100%, MNIST 표본 전체 정확도 ≥ 97%)이 모두 통과인지 확인합니다. 불일치 줄은 빨간색, 표본 종류별 집계도 함께 나옵니다.
   - 측정값 (230장): 전처리 230/230 일치(최대 차이 7e-7), 예측 230/230 일치(점수 최대 차이 6e-6), 정확도 230/230, 한 장 약 50ms.
4. 마지막으로 `index.html`에서 0~9를 직접 그려 확인합니다.

- GitHub Pages에는 검증 데이터가 없으므로 배포된 `검증.html`은 "검증 데이터가 없습니다"라고 나옵니다 (정상).

## 배포와 주의

- GitHub Pages는 `main` 브랜치 루트를 배포하고, 루트 `index.html`이 이 폴더로 이동시킵니다. 폴더 이름·위치를 바꾸면 루트 `index.html`의 이동 경로도 고칩니다.
- 외부 CDN·라이브러리를 추가하지 않습니다.
- 페이지 맨 위 "학번 2601953 이름 안서연" 표시줄(`index.html`, `검증.html`)은 과제 요구사항이므로 지우지 않습니다.
