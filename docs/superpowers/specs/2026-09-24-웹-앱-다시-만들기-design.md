# 설계: 손글씨 인식 프로그램을 Superpowers로 다시 만들기

> Superpowers(v6.4.1) 설치 후 `superpowers:brainstorming` 스킬로 만든 설계 문서입니다.
> 저장소의 결과물 중 Superpowers 설치(커밋 `124a209`) 전에 만든 것을 모두 이 설계로 새로 만듭니다. 설치 전 결과물과 그 설계 문서·계획서는 새 결과물로 바꾸면서 폴더에서 지웁니다 (과거 커밋에는 기록으로 남음).

## 1. 목적과 범위

- **목적**: 과제의 "Superpowers를 활용해 만든다"는 요구를 실제로 지킨다. 설치 전에 만든 결과물(노트 3.3 데스크톱 앱, 3.4 문서, 3.5 웹 앱)을 설치 후 Superpowers 절차(설계 → 계획 → 서브에이전트 구현 → 검토 → 배포)로 새로 만든다.
- **새로 만들 것** (기존 파일을 지우고 이 문서만 보고 새로 작성, 기존 코드를 베끼지 않음)
  - 노트 3.3 데스크톱 앱: `desktop_version/model.py`, `train.py`, `app.py`, `make_shortcut.py`, `app_icon.ico`, `mnist_cnn.pt`(새로 학습), `README.md`
  - 노트 3.4 문서: 루트 `CLAUDE.md`, `desktop_version/CLAUDE.md`, `web_version/CLAUDE.md`, `CLAUDE_전역.md`(사용자 전역 지침의 사본, 같은 규칙을 새로 정리)
  - 노트 3.5 웹 앱: `web_version/` 전체(`index.html`, `스타일.css`, `그림판.js`, `전처리.js`, `모델.js`, `앱.js`, `검증.html`, `가중치.bin`, `가중치정보.json`), `desktop_version/가중치내보내기.py`, `desktop_version/검증데이터만들기.py`, 루트 `index.html`
- **지울 것**: 설치 전 설계 문서 `docs/superpowers/specs/2026-09-24-웹-데스크톱-버전-분리-design.md`, 설치 전 계획서 `docs/superpowers/plans/2026-09-24-웹-데스크톱-버전-분리.md`
- **그대로 둘 것** (설치 후 만든 것 또는 설정): `.claude/settings.json`, `.gitignore`, `검사/` 스크립트 5개, 재검증 계획서 `…-재검증.md`
  - `검사/` 스크립트는 이번 작업의 **합격 기준**이다. 단, `검사/데스크톱_회귀.py`의 "첫 커밋 `55382a4`와 같다" 검사는 데스크톱 앱을 새로 만들면 의미가 없으므로, "데스크톱 파일 4개가 있고 `app.py` 경로 정확도 ≥ 97%, 빈 그림은 None"만 남기도록 고친다.
- **성공 기준**
  1. `검사/` 스크립트 5개가 모두 통과.
  2. 새 모델의 MNIST 시험 정확도 ≥ 99%.
  3. `main`에 합친 뒤 깃허브 페이지 배포 성공, 시크릿 창에서 학번·이름과 인식 확인.
  4. 합치기 전까지 지금 배포된 페이지는 건드리지 않는다.

## 3. 부품 설계

### 0) 데스크톱 앱 (노트 3.3, `desktop_version/`)

- **`model.py`**: `숫자인식CNN(nn.Module)`. 특징추출 = [합성곱 1→32 → 배치정규화 → ReLU → 합성곱 32→32 → 배치정규화 → ReLU → 2x2 최대풀링 → 드롭아웃 0.25] + [합성곱 32→64 → 배치정규화 → ReLU → 합성곱 64→64 → 배치정규화 → ReLU → 2x2 최대풀링 → 드롭아웃 0.25], 합성곱은 모두 3x3·패딩 1. 분류기 = 펼치기 → 전결합 3136→256 → ReLU → 드롭아웃 0.5 → 전결합 256→10. (내보낼 값 870,634개 = 3,482,536바이트가 `검사/가중치_검사.py`의 기준과 맞는 구조.)
- **`train.py`**: MNIST를 `desktop_version/data`(`__file__` 기준)에 내려받고, 정규화(평균 0.1307, 표준편차 0.3081) + 가벼운 증강(작은 회전·이동)으로 5에폭 학습, 에폭마다 시험 정확도를 출력하고 가장 좋을 때 `desktop_version/mnist_cnn.pt`(`state_dict`)로 저장. CPU에서 동작.
- **`app.py`**: tkinter 그림판(280x280, 검은 배경 흰 글씨, 펜 18, 캔버스와 PIL 이미지에 동시에 그림). 붓을 뗄 때마다 인식해 예측 숫자, 신뢰도, 0~9 확률 막대를 보여 주고, 지우기 버튼이 있다. 다른 스크립트가 가져다 쓰는 이름: `프로젝트폴더`, `가중치경로`, `아이콘경로`, `앱ID`, `캔버스크기`(=280), `평균`, `표준편차`, `모델_불러오기()`, `전처리(그림: PIL.Image) → Tensor(1,1,28,28) | None`(빈 그림이면 None, 전처리 3단계는 루트 CLAUDE.md와 같음). 창은 `if __name__ == "__main__":` 안에서만 만든다(import해도 창이 뜨지 않음).
  - 노트 3.3.2.5 더블클릭 실행: 파일 경로는 모두 `__file__` 기준, 라이브러리·가중치 오류는 대화상자로 보여 주고, 더블클릭으로 생긴 콘솔 창은 숨긴다. 윈도우 작업 표시줄 묶음용 `앱ID`를 설정한다.
- **`make_shortcut.py`** (노트 3.3.2.6 b): `app_icon.ico`를 만들고(Pillow), 바탕 화면에 "손글씨 숫자 인식기" 바로가기를 만든다. `pythonw.exe`로 실행(검은 창 없음), 아이콘 지정, `app.py`와 같은 `앱ID`를 넣어 작업 표시줄 고정 가능. `pywin32` 필요.
- **`README.md`**: 파일 구성, 실행 방법(PowerShell), 다시 학습하는 법, 실제로 측정한 시험 정확도.

### a) 데스크톱 쪽 스크립트 (`desktop_version/`)

- **`가중치내보내기.py`**: `app.py`에서 `가중치경로`, `모델_불러오기`, `평균`, `표준편차`를 가져온다. 합성곱 4개 각각에 뒤따르는 배치정규화를 합성곱 가중치·편향에 합쳐(`W' = W·γ/√(σ²+ε)`, `b' = (b−μ)·γ/√(σ²+ε) + β`) 텐서 12개(합성곱 4 + 전결합 2의 가중치·편향)를 순서대로 `web_version/가중치.bin`에 쓴다. 값 870,634개, 3,482,536바이트.
  - `가중치정보.json`: `{"원본", "입력형상": [1,28,28], "평균": 0.1307, "표준편차": 0.3081, "층": [...]}`. `층`은 계산 순서대로 `{"종류": "conv"|"relu"|"maxpool"|"flatten"|"linear", "이름", "가중치": {"형상", "오프셋", "개수"}, "편향": {...}}` (가중치가 없는 층은 `종류`, `이름`만). 오프셋은 float 개수 단위.
  - `main()` 함수로 실행하고, 마지막에 무작위 입력으로 합친 계산과 PyTorch 출력을 비교해 `PyTorch와 변환 결과 최대 차이: X`를 출력한다. 3x3·패딩 1·보폭 1이 아닌 합성곱이 나오면 멈춘다.
  - 같은 `mnist_cnn.pt`로 다시 실행하면 바이트가 같은 파일이 나와야 한다.
- **`검증데이터만들기.py`**: `app.py`의 `전처리`, `모델_불러오기`, `캔버스크기`를 쓴다. `main()`이 280x280 흑백 그림 230장을 만든다: MNIST 10배 확대 50장(`MNIST 10배`), 60~280px 임의 크기·위치 MNIST 150장(`MNIST 크기·위치`, 일부는 가장자리에 붙임), `app.py`와 같은 방식(선 + 원, 펜 18)으로 0~9 획을 그린 30장(`획 그리기`). 난수 고정.
  - 각 그림의 정답, 파이썬 전처리 결과(784개), 파이썬 점수(10개)를 `web_version/검증데이터.json`에, 그림 바이트를 `web_version/검증데이터.bin`에 저장한다 (`.gitignore` 대상).
  - 종류마다 `  {종류}: {n}장, 파이썬 정확도 {맞음}/{n}` 줄을 출력한다. 첫 인자로 MNIST 장수를 바꿀 수 있다(기본 200).

### b) 웹 쪽 (`web_version/`)

| 파일 | 하는 일 | 공개 이름 |
|---|---|---|
| `전처리.js` | `app.py` `전처리()`와 같은 값: 여백 자르기 → 긴 변 20px로 Pillow LANCZOS와 같은 계산(계수, 22비트 고정소수점, 가로 먼저) → 28x28 가운데 배치 → 밝기 무게중심을 (14, 14)로 이동(파이썬 `round()`의 짝수 반올림) → 정규화. 빈 그림이면 `null` | `전처리.전처리하기(픽셀, 가로, 세로, 평균, 표준편차) → Float32Array(784) \| null` |
| `모델.js` | 두 파일을 `fetch`해 가중치를 `Float32Array`로 복사 없이 읽고(바이트 길이·형상·오프셋 미리 검사) 합성곱(패딩 1)·ReLU·2x2 최대풀링·펼치기·전결합을 계산 | `모델.모델_불러오기() → Promise<{추론(입력) → Float32Array(10), 평균, 표준편차}>` |
| `그림판.js` | 280x280 캔버스, 검은 배경 흰 글씨, 펜 18. 포인터 이벤트로 마우스·터치·펜 처리, 두 번째 손가락과 오른쪽 버튼 무시, 그릴 때 화면 스크롤 막기 | `그림판.그림판_만들기(캔버스, {펜두께, 다그렸을때}) → {픽셀가져오기(), 지우기(), 가로, 세로}` |
| `앱.js` | 붓을 뗄 때마다 전처리 → 추론 → 소프트맥스 → 예측·신뢰도·0~9 확률 막대. 불러오는 중에 그린 그림은 불러온 뒤 인식. `file://`로 열면 로컬 서버 안내 | |
| `index.html`, `스타일.css` | 맨 위 `<header>학번 2601953 이름 안서연</header>`, 그림판, 지우기 버튼, 결과 영역 | |
| `검증.html` | 검증 데이터를 JS 경로로 처리해 파이썬과 대조하고 성공 기준 표를 그린다 | |

- `전처리.js`, `모델.js`는 브라우저 전역 이름과 Node.js `module.exports`를 모두 지원한다.
- 루트 `index.html`: 학번·이름을 보여 주고 `web_version/`으로 이동 (`<meta http-equiv="refresh">` + `location.replace`).

### c) 검사 스크립트와 맞춰야 할 화면 약속 (바꾸면 `검사/`가 실패함)

- `index.html`: `#그림판`(280x280 canvas), `#지우기`, `#예측`(숫자 한 글자 또는 `?`), `#신뢰도`(불러오는 중 → 불러온 뒤 "숫자를 그려 보세요" 포함 → 인식 후 신뢰도). `file://`에서는 `#신뢰도`에 `python -m http.server` 안내. 학번·이름 문구 그대로.
- 가중치는 `가중치.bin` 하나만 `.bin`으로 요청한다.
- `검증.html`: `#요약`은 처음에 "검증 중…", 끝나면 표(`table tbody tr`, 칸: 항목·기준·실측·판정)를 담는다. 항목 이름은 `순전파 일치`(같은 28x28 입력의 확률 최대 절대차 ≤ 1e-4), `전처리 일치`(차이 1e-4 미만 표본 100%), `예측 일치`(100%), `전체 정확도`(MNIST 표본 ≥ 97%), 판정은 `통과`/`실패`. 데이터가 없으면 `#요약`에 안내 문구.

### d) CLAUDE.md 3개와 `CLAUDE_전역.md` (노트 3.4)

- 루트: 두 버전의 관계와 흐름, 공통 규칙(한글 식별자, 전처리 3단계, 학번·이름 줄과 `CLAUDE_전역.md`를 지우지 않음, `검사/` 실행법 — bash와 PowerShell 둘 다, Playwright 준비 명령 포함).
- `desktop_version/`: 환경 제약(Windows, PyTorch CPU), 실행 명령, 파일 연결 관계, 두 스크립트 설명.
- `web_version/`: 로컬 실행법(`file://` 불가), 가중치 파일 형식, 파이썬과 맞춰야 할 지점, 검증 절차.
- `CLAUDE_전역.md`: 사용자 전역 지침(`~/.claude/CLAUDE.md`)의 사본. 맨 위에 작성 시각과 "사본이며 세션에 자동으로 읽히지 않는다"는 안내. 내용은 사용자가 정한 규칙 그대로: 1 설명 방식(쉬운 말, 번호 순서, 한 일과 할 일 구분), 2 코딩 전에 생각, 3 단순하게, 4 목표를 정하고 검증, 5 배포·제출·되돌리기 어려운 작업, 6 한국어 작성 규칙, 7 새 파일 작성 시각 표시(`TZ=Asia/Seoul`).

## 4. 데이터 흐름

```
[데스크톱] mnist_cnn.pt → 가중치내보내기.py → 가중치.bin + 가중치정보.json
[웹]      그림판.js(280x280) → 전처리.js(784) → 모델.js(점수 10) → 앱.js(확률, 표시)

```

## 5. 오류 처리

- 가중치 파일이 깨졌거나 형식이 다르면 `모델.js`가 알아보기 쉬운 한글 오류를 내고 화면 `#신뢰도`에 보여 준다.
- 빈 그림, 가장자리의 작은 점: 오류나 `NaN` 없이 `?` 또는 숫자 하나.
- 불러오기 전에 그린 그림은 기억했다가 불러온 뒤 인식한다.

## 6. 진행 방법과 위험

- 작업 브랜치 `claude/bold-tesla-9h49s1`에서 한다. 먼저 새로 만들 파일과 설치 전 문서를 지우고(`git rm`), 태스크마다 서브에이전트가 이 문서만 보고 새로 쓴다. 옛 코드는 참고하지 않는다.
- 순서: 데스크톱 앱(모델 → 학습 → 앱 → 바로가기) → 내보내기·검증 데이터 스크립트 → 웹(순전파 → 전처리 → 화면 → 검증 페이지) → 문서.
- 모든 검사를 통과한 뒤에만 `main`에 합친다. 실패하면 `main`은 그대로라 배포된 페이지에 영향이 없다.
- 위험: JS 전처리가 파이썬과 어긋나면 손 그림 인식률이 떨어진다 → `검증.html`의 전처리 일치와 `검사/웹_검사.cjs`로 잡는다.
