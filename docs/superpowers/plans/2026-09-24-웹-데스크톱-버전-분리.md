# 구현 계획서: 웹·데스크톱 버전 분리

> 설계: `docs/superpowers/specs/2026-09-24-웹-데스크톱-버전-분리-design.md`
> 이 문서는 Superpowers의 writing-plans 형식(태스크 + 태스크별 검증)을 따릅니다. 이 세션에는 Superpowers 플러그인이 없어 Claude가 같은 형식으로 직접 작성했고, 태스크도 서브에이전트 대신 한 세션에서 순서대로(인라인) 실행했습니다.
> 작업 브랜치: `claude/exciting-bell-8wnu8k` → 검증 후 `main`에 병합 → GitHub Pages 배포.

## 계획 단계에서 바로잡은 점

- **텐서 개수**: `state_dict`에는 텐서가 32개(배치정규화 통계 포함) 있지만, 배치정규화를 합성곱에 합치면 웹으로 보낼 텐서는 12개다. 설계 문서에 12개로 적었다. `state_dict`의 값은 871,402개이고, 배치정규화를 합친 뒤 `가중치.bin`에는 870,634개(3,482,536바이트, 약 3.5MB)가 들어간다.
- **전처리 위치**: 노트의 `preprocess.py`는 이 프로젝트에 없다. 전처리는 `app.py`의 `전처리()`이므로 새 스크립트는 `app.py`에서 가져다 쓴다.
- **MNIST 데이터**: `train.py`가 받은 `desktop_version/data`를 검증 데이터 스크립트가 다시 쓴다 (없으면 내려받음).

## 태스크 (2026-09-24 20:24 노트 형식에 맞춰 순서 정리)

정답 데이터(검사 수단)를 구현보다 먼저 만들고, 그 검사를 통과하도록 구현한다 (Superpowers test-driven-development 방식). 그래서 파이썬 쪽 준비(태스크 1~3)를 먼저, 자바스크립트 구현(4~6)을 다음에, 문서(7)를 마지막에 둔다.

- 태스크 1~3은 파이썬 쪽 준비, 4~6은 자바스크립트 구현, 7은 문서다.
- 순전파(태스크 4)가 전처리(태스크 5)보다 앞인 이유: 순전파는 정답 데이터의 28x28 입력만으로 따로 검사할 수 있고, 전처리는 순전파까지 이어 붙여야 전체 정확도를 잴 수 있다.
- 화면(태스크 6)은 `모델.js`와 `전처리.js`를 불러 쓰므로 태스크 4, 5 뒤에 만든다.
- 태스크 7은 앞 6개의 결과를 모두 알아야 쓸 수 있으므로 마지막이다.

| 항목 | 기준 | 실측 |
|---|---|---|

| 전처리 일치 | 파이썬 전처리 결과와 차이 1e-4 미만인 표본 100% | 230/230 (최대 7.2e-7) |

- 노트(교수 버전)의 웹 앱은 상위 3개 후보를 보여 주지만, 이 프로젝트의 데스크톱 앱(`app.py`)이 0~9 전체 확률 막대를 보여 주므로 웹도 같게 두었다 (결정 4: 데스크톱과 동등).

## 실제 진행 기록

이 세션은 서브에이전트 없이 한 대화에서 인라인으로 진행했고, 실제 순서는 위 표와 조금 달랐다. 처음 한 일은 폴더 분리, 가중치 내보내기, `모델.js`였다. `모델.js`는 Node.js에서 PyTorch 점수와 MNIST 2000장을 대조하는 방식으로 먼저 검사했다 (예측 2000/2000 일치, 점수 최대 차이 7.6e-6). 그 뒤 `검증데이터만들기.py`와 `검증.html`로 전처리까지 검사했다. 위 표는 노트의 태스크 구성에 맞춰 정리한 것이고, 각 태스크의 검증은 모두 실제로 실행한 결과다.

## 태스크별 세부

### 1. 폴더 분리와 데스크톱 회귀 확인
- `git mv`로 `model.py train.py app.py make_shortcut.py mnist_cnn.pt app_icon.ico` → `desktop_version/`.
- 파이썬 파일 4개(`model.py`, `train.py`, `app.py`, `make_shortcut.py`)는 **한 글자도 고치지 않는다.** `app.py`, `make_shortcut.py`는 이미 `__file__` 기준 경로라 옮겨도 그대로 동작한다. `train.py`는 상대 경로(`mnist_cnn.pt`, `./data`)를 쓰므로 코드를 고치는 대신 "`desktop_version/` 안에서 실행한다"를 `desktop_version/CLAUDE.md`에 적는다.
  - 기록: 처음에는 `train.py`의 경로를 `__file__` 기준으로 고쳤다가, "데스크톱 코드는 수정하지 않는다"는 설계에 맞춰 원본으로 되돌렸다 (2026-09-24 20:20). 지금 4개 파일은 분리 전 원본과 바이트 단위로 같다.
- 회귀 확인: 옮긴 뒤 `app.py` 터미널 실행과 더블클릭 실행이 여전히 되는지 확인한다. 바탕 화면 바로가기는 옛 경로를 가리키므로 `make_shortcut.py`를 다시 실행한다.
- 루트 `index.html`은 `web_version/`으로 이동시키는 페이지로 두고, 이동이 막혀도 학번·이름이 보이게 한다.

### 2. 가중치 내보내기
- `app.py`의 `모델_불러오기()`, `평균`, `표준편차`, `가중치경로`를 import.
- 합성곱 + 배치정규화 → `W' = W·γ/√(σ²+ε)`, `b' = (b−μ)·γ/√(σ²+ε) + β`.
- 3x3·패딩 1·보폭 1이 아닌 합성곱이 나오면 멈춘다 (`모델.js`가 지원하지 않으므로).

### 3. 검증 데이터 만들기
- 표본: MNIST 10배 확대 50장, 크기·위치를 바꾼 MNIST 150장(일부는 캔버스 가장자리에 붙임), `app.py` 방식(선 + 원, 펜 18)으로 그린 획 30장. 난수 고정. 각 표본에 그림, 정답 라벨, 파이썬 전처리 결과, 파이썬 점수를 담는다.
- 검증 데이터(약 18MB)는 다시 만들 수 있으므로 `.gitignore`로 뺀다. 배포된 `검증.html`은 데이터가 없다고 안내한다.

### 4. 자바스크립트 순전파
- 합성곱(패딩 1), ReLU, 2x2 최대풀링, 전결합. 입력·중간값은 `Float32Array`, 메모리 순서는 PyTorch와 같게 `[채널][높이][너비]`.
- 가중치는 `new Float32Array(바이너리, 오프셋*4, 개수)`로 복사 없이 읽는다.
- `검증.html`의 순전파 검사: 파이썬이 전처리한 입력을 그대로 넣어 전처리 차이와 섞이지 않게 한다.

### 5. 자바스크립트 전처리와 전체 정확도
- 여백 제거 → 긴 변 20px LANCZOS 축소(Pillow의 계수 계산·22비트 고정소수점·가로 먼저) → 28x28 가운데 배치(`(28−크기)//2`) → 무게중심 (14, 14) 이동(빈 곳 0) → 정규화.
- 파이썬 `round()` 짝수 반올림을 구현한다.
- `검증.html`: 그림 → 전처리 → 순전파 전체 경로로 정확도를 잰다.

### 6. 웹 앱 화면
- `그림판.js`: 포인터 이벤트(마우스·터치), 펜 두께 18, 검은 배경에 흰 글씨. 두 번째 손가락과 오른쪽 버튼은 무시.
- `앱.js`: 붓을 뗄 때마다 전처리 → 추론 → 소프트맥스 → 예측·신뢰도·확률 막대.

### 7. 문서 3개
- 루트: 두 버전 관계 + 공통 규칙(한글 식별자, 전처리 3단계)만.
- `desktop_version/`: 예전 루트 내용(환경 제약, 실행 방식, 더블클릭 실행) + 파일 연결 관계 + 가중치 내보내기 + 검증 데이터.
- `web_version/`: 로컬 실행법(`file://` 불가) + `가중치.bin` 형식 + 파이썬과 맞춰야 할 지점 + 검증 절차.
