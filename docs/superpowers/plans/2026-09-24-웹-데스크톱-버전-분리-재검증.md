**Goal:** 설계 문서의 7개 태스크 결과물을, 누구나 다시 돌릴 수 있는 검사 스크립트(`검사/`)로 하나씩 증명하고, 검사가 잡아낸 문제가 있으면 고친다.

**Architecture:** 구현은 이미 `main`에 있다(이전 계획서 `2026-09-24-웹-데스크톱-버전-분리.md`, Superpowers 설치 전 작성). 이 계획은 Superpowers 설치 후 writing-plans 스킬로 쓴 것으로, 태스크마다 "검사 작성 → 일부러 고장 내서 검사가 실패하는지 확인(red) → 되돌려 통과 확인(green) → 커밋" 순서로 진행한다. 파이썬 검사는 PyTorch로, 웹 검사는 로컬 서버 + Playwright(Chromium)로 실제 브라우저에서 돌린다.

**Tech Stack:** Python 3 + PyTorch CPU + torchvision + Pillow, Node.js + Playwright(전역 설치, 검사 전용), 순수 자바스크립트 웹 앱(라이브러리 없음)

## Global Constraints

- 모든 코드와 주석은 한글, 식별자도 한글 (`CLAUDE.md` 공통 규칙).
- 새 파일 맨 위에 `작성: YYYY-MM-DD HH:MM` 주석, 시각은 `TZ=Asia/Seoul date "+%Y-%m-%d %H:%M"`으로 확인 (`CLAUDE_전역.md` 7절).
- `desktop_version/`의 `model.py`, `train.py`, `app.py`, `make_shortcut.py`는 **한 글자도 고치지 않는다** (설계 c)).
- 웹 버전은 실행 시 외부 라이브러리, CDN, 빌드 도구 0개 (설계 결정 6). Playwright는 검사할 때만 쓰고 웹 페이지는 쓰지 않는다.
- 정규화 상수 평균 `0.1307`, 표준편차 `0.3081`.
- 페이지 맨 위 "학번 2601953 이름 안서연"은 지우지 않는다.
- 검사가 만드는 파일(`desktop_version/data/`, `web_version/검증데이터.*`)은 `.gitignore` 대상이며 커밋하지 않는다.

## Review Focus

설계가 직접 말하지 않지만 사용자(채점자)가 만날 가능성이 큰 입력 5가지. 각 줄의 검사는 태스크 6에 들어 있다.

1. **모델을 불러오는 중에 그리기** (느린 네트워크) → 불러오기가 끝나면 그린 숫자를 인식해야 한다.
2. **지우기 후 빈 그림판** → 예측이 `?`로 돌아가고 오류가 없어야 한다.
3. **그림판 가장자리의 아주 작은 점** → 페이지 오류나 `NaN` 없이 숫자 하나를 예측해야 한다.
4. **마우스 오른쪽 버튼으로 끌기** → 그려지지 않아 예측이 `?`로 남아야 한다.
5. **`index.html`을 파일로 직접 열기(`file://`)** → 학번·이름이 보이고 로컬 서버 안내 문구가 나와야 한다.
